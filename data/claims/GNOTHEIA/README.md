# GNOTHEIA Synthetic Insurance Dataset

> **Published by:** [Gratex International a.s.](https://www.gratex.com)  
> **Project:** [InnovAIte](https://www.innovaite.sk/) — InnovAIte Slovakia
> **License:** Apache 2.0  
> **Version:** 1.0.0  
> **Contact:** info@gratex.com

A synthetic insurance claims dataset designed for AI systems that evaluate insurance claims using OMG SBVR business rules, structured claim polycontexts and synthetic claim-related documents.

The dataset main goal is to support:
- LLM fine-tuning pipeline
- SBVR reasoning benchmarks
- insurance claim AI evaluation

The dataset is generated entirely synthetically using the SyDaFa (Synthetic Data Factory) engine within the GNOTHEIA AI ecosystem.

## Overview

The main contribution is an SBVR rules-first, LLM-oriented dataset for learning and benchmarking how models interpret documents, structured claim context and policy information using curated collection of SBVR rules. This dataset is a collection of **synthetic insurance data** generated by Synthetic Data Factory hereinafter **SyDaFa**,  the data generation engine of the **GNOTHEIA** AI ecosystem. GNOTHEIA (from *GNOsis* + *aleTHEIA* — truth through knowledge) is a comprehensive AI system designed to augment insurance claim assessment for property (household and building protection)  insurance, developed as part of the **InnovAIte** project funded under the Slovak national AI strategy. GNOTHEIA is an AI ecosystem whose central goal is to use fine tuned model that can assess insurance claims by applying SBVR business rules to heterogeneous claim evidence. While traditional rule engines work well when inputs are already normalized into explicit facts, GNOTHEIA AI ecosystem uses formal SBVR rules to evaluate claim polycontext (claim metadata, policy metadata, incoming documents) powered by AI - LLM with open weights.  

All data in this collection is **fully synthetic** — no real customer data, no personally identifiable information (PII) is present nor was used for data generation. The synthetic generation process starts from anonymised structural patterns derived from real-world insurance products and recreates realistic claim scenarios for AI training, evaluation, fine-tuning and research.

### The dataset is intended for:
- Support LLM **Training and fine-tuning** pipeline for the insurance claims domain
- OMG SBVR **rules evaluation and reasoning** in the context of incoming insurance claim documents using AI
- **Research** in AI driven ecosystems, structured business rules, document content understanding
- **Benchmarking AI** systems against SBVR-formalised insurance claims and policy logic.

### Not intended for
- Legal advice or binding claim determinations.
- Processing real customer data without proper governance.
- Automated claims settlement without human oversight.

## How this dataset was created

SyDaFa generates synthetic data using **OMG SBVR rules-first** strategy: instead of scanning existing documents and extracting structure, it constructs the entire claim context from generated loss event scenarios and corresponding rule set — structured metadata about claim and insurance policy, supporting documents and then derives the individual documents from this context. This is the reverse of traditional pipeline approaches.

The generation pipeline:

```
claim scenarios
        ↓
rule set selection (deterministic)
        ↓
polycontext generation (claim data, policy data, claim related documents - text format)

```
Each generated record contains well formed data in JSON format.

## Dataset Structure

There are two datasets available:
- polycontext dataset - contains structured claim data, structured policy data, and claim-related documents side by side within a single JSON object, 
- SBVR rules dataset - set of selected SBVR rules in the field of property and building insurance, covering perils which are currently predominant in the retail household insurance.

### 1. Synthetic Claim Polycontexts - `polycontexts`
(GNOTHEIA's core data structure) is a unified, structured representation of all information relevant to a single insurance claim. It aggregates metadata, insurance claim data, policy data, documents and applicable OMG SBVR rules into a single JSON object.
The dataset is provided as a parquet file `data.parquet` file where each contains a full polycontext JSON object. It contains two additional top-level fields:
- `id`: sequential integer from 1 to 863
- `note`: a string with the format `"Claim scenario: <coverage> / <insured_subject> / <risk>"`

**Top-level fields one record:**

| Field | Type | Description |
|---|---|---|
| `id` | integer | Sequential record identifier (1–863) |
| `note` | string | Claim scenario label: `"Claim scenario: <coverage> / <insured_subject> / <risk>"` |
| `data` | object | Full polycontext JSON object |

**Fields inside `data`:**

| Field | Type | Description |
|---|---|---|
| `id` | string | Unique polycontext identifier |
| `documentMetadataDates_evaluatedDateTime` | string | Evaluation date from document metadata |
| `businessDates_evaluatedDateTime` | string | Business evaluation date |
| `claim` | object | Full claim object — see below |
| `policy` | object | Insurance policy details |
| `contextDocuments` | array | List of claim documents |
| `rules` | array | Applicable SBVR rules |
| `summary` | object | Empty summary placeholder |

**Claim object fields:**

| Field | Description |
|---|---|
| `claimId` | Unique claim identifier |
| `claimant` | Synthetic claimant name |
| `damagedDescription` | Short description of damaged property |
| `dateOfLoss` | Date of loss occurrence |
| `dateOfReported` | Date of loss reported to insurer |
| `lossEvent` | Type of insured event — peril covered within the policy |
| `lossSummary` | Detailed loss description |
| `damagedItems` | List of insured items damaged during the loss event, follows insured subjects covered by the insurance policy, in this dataset limited to one insured subject intentionally | 

**Policy object fields:**

| Field | Description |
|---|---|
| `policyId` | Unique policy identifier |
| `policyStatusToDateOfLoss` | policy status in the time of loss (Issued, Active, Expired) |
| `product` | `PHI` (Property Household Insurance) or `PBI` (Property Building Insurance) |
| `coveragePeriodFrom` | start date of coverage period |
| `coveragePeriodTo` | end date of coverage period |
| `coverage` | the list of coverages (building or household), contains `insuredLocation` - synthetic address and the list of `insuredSubjects` | 
| `insuredSubjects` | The list of subjects of insurance coverage by the insurance policy, contains the list of covered `risks` |
| `risks` | Name of the risk - event covered by the insurance policy |

**Rules**

The **SBVR rules** contains business rules formalised in **OMG SBVR (Semantics of Business Vocabulary and Business Rules)** format — the OMG standard for expressing business logic in a structured, unambiguous, machine-readable yet human-readable way.

These rules are used by SyDaFa during polycontext generation. Only rules relevant for polycontext claim case are included within the polycontext itself. 

**Purpose:** Rule-based claim evaluation, LLM fine-tuning on structured reasoning, SBVR format learning, insurance compliance AI.

**Important note:** Fields `status` and `statusReasoning` are intentionally blank, since these fields are populated only when the GNOTHEIA Polycontext Processor evaluates a particular rule against polycontext using an identified model, prompt and rule release. They are outputs of a versioned evaluation run, not static attributes of the source polycontext. 

**Risk groups:** Fire, Water, Natural Disaster, Theft, Weather, Glass, General, Extended warranty

**Fields per rule (inside polycontext):**

| Field | Description |
|---|---|
| `id` | Unique rule identifier (integer) |
| `rule` | Full SBVR rule text in English |
| `status` | Intentionally blank `""` — the label to be evaluated |
| `statusReasoning` | Set to `[]` — to be filled by the model based on evaluation |

> **Note on SBVR:** SBVR is an OMG standard (https://www.omg.org/spec/SBVR/) that enables expressing business rules using controlled natural language structured around deontic modalities (obligation, prohibition, permission). It bridges the gap between legal/policy text and machine-executable logic, making it ideal for insurance compliance automation.

**Synthetic Insurance Claim Documents - `contextDocuments`**

Synthetic text documents representing the various document types that accompany an insurance claim. Generated by SyDaFa in English.

**Fields per document:**
| Field | Description |
|---|---|
| `extractedDocumentId` | Unique document identifier (integer) |
| `extractedDocumentContent` | Generated document content in MD format |
| `documentMetadataDates_createdDateTime` | Date time of document creation based on metadata |
| `businessDates_filingOfficeDateTime` | Date time of document creation in the production system. The underlaying production system is the only source of the truth (data).  |
| `itSystemDates_enteredDateTime` | Document creation date time in the GNOTHEIA ecosystem |
| `channel` | Source document channel - email, hardcopy, form |
| `documentType` | Document type |

**Current document types:**

| Type |  Description |
|---|---|
| `first_notice_of_loss` | First Notice of Loss (FNOL) — the insured's initial claim submission describing the event, date, circumstances, and preliminary damage assessment |
| `photo_evidence` | Photographic evidence of damage — text descriptions of images showing damaged property (windows, structures, contents) |
| `invoice` | Repair or replacement invoices, receipts, and expense documentation supporting the claimed amount |
| `police_confirmation` | Police report confirming theft, vandalism, or third-party involvement in the insured event |
| `online_form_submission` | Digital first notice of loss submitted via insurer's online portal |

### 2. SBVR Rules dataset

The SBVR Rule dataset is available in parquet format (`rules-dataset.parquet`. The scope of usage of each rule is given by the rule's tags (attributes)
- coverage - applies to specific coverage or all coverages if not defined,
- product - applies to specific product or all products,
- insured_subject - applies to specific insured subject or all, 
- risk - applies to specific risk or all risks. 
None of these tags is mandatory.

**Fields per rule:**
| Field | Description |
|---|---|
| `s_id` | Unique rule identifier (e.g. `BR-100001`) |
| `s_rule` | Rule text in English, SBVR format |
| `s_product_code` | `PBI` or `PHI` — product scope of the rule |
| `s_coverage_type` | Coverage type scope (e.g. `Building`) |
| `s_insured_subject` | Insured subject scope (e.g. `Household contents`, `Flat`, `Outbuilding`) |
| `s_risk_group` | Risk group scope (e.g. `Fire`, `Water`, `Natural`, `Theft`) |
| `s_risk` | Specific risk scope (e.g. `Flood`, `Storm`, `Burglary`) |
| `s_gate_name` | Claim assessment gate (`FIRST_NOTIFICATION_OF_LOSS`, `CLAIM_REGISTRATION`, `CLAIM_ASSESSMENT`) |
| `s_gate_type` | Gate type (`ENTRY`) |
| `n_order` | Gate order |
| `d_valid_from` | Rule validity start date |
| `d_valid_to` | Rule validity end date |
| `s_recommended_statuses` | Comma-separated list of recommended evaluation statuses outcomes for the rule |

**Total rules:** 490

## Key Insurance Domain Concepts

**Products covered:**
- `PHI` — Property Household Insurance (movable contents)
  - contains insured subjects: Household contents, Debris removal expenses, Electronic Devices, Waterleakage expenses, ...
- `PBI` — Property Building Insurance (buildings and structures)
  - contains insured subjects: Family house or flat, Outbuildings, Debris removal expenses, Waterleakage expenses, ...


**Perils:** fire, water damage, theft, natural disaster, weather, glass breakage, liability, extended warranty, vandalism, technical failure

For readers unfamiliar with Central European property insurance terminology:

| Term | Definition |
|---|---|
| **PHI** | *Property Household Insurance* — covers movable contents of a residence (furniture, electronics, valuables) against fire, theft, water damage, and other perils |
| **PBI** | *Property Building Insurance* — covers the physical structure of buildings (walls, roof, fixed installations) against structural damage perils |
| **FNOL** | *First Notice of Loss* — the initial claim notification. In Slovak: *Hlásenie poistnej udalosti* |
| **Polycontext** | GNOTHEIA's unified claim context object — aggregates all information about a claim into a single structured record for AI processing |
| **SBVR** | *Semantics of Business Vocabulary and Business Rules* — OMG standard for formalising business rules in controlled natural language |
| **Deontic modality** | In SBVR: the logical category of a rule — *obligation* (must), *prohibition* (must not), *permission* (may) |
| **SyDaFa** | *Synthetic Data Factory* — the GNOTHEIA component that generates all synthetic datasets |

## Data Quality & Ethics

**No real personal data:** All claimant names, addresses, personal identifiers etc. are synthetically generated. 

**Schema validation:** Every polycontext record passed strict JSON schema validation before inclusion. Invalid outputs were quarantined and excluded.

**Language:** Documents are generated in English (`en`). SBVR rules are in English. 

**Apache 2.0 license:** This dataset is free to use for commercial and research purposes with attribution.

## Future work and consideration, known limitations

This dataset delivers insurance-specific context alongside hundreds of SBVR rules designed for AI-driven ecosystems. To enhance the complexity and robustness of this comprehensive resource, the following initiatives are planned to add greater depth to this effort:

- Expand polycontext items using real-world statistical distributions.
- Incorporate additional document types with more granular structural details per type.
- Add liability coverage and assistance services, which are prevalent components of property insurance.

## Getting Started

Here is a simple Python script to load and inspect the datasets:

```python
import pandas as pd

# Load the datasets using pandas
polycontexts_df = pd.read_parquet('data/polycontexts.parquet')
rules_df = pd.read_parquet('data/rules-dataset.parquet')

# Print the first polycontext
print("--- First Polycontext ---")
# Convert the first row to JSON for pretty printing
print(polycontexts_df.iloc[0].to_json(indent=2))

# Print the first rule
print("\n--- First Rule ---")
print(rules_df.iloc[0].to_json(indent=2))
```
